Return a discovery window of recent enactments, optionally filtered by bundle id. This is a discovery aid, not an existence check or required coverage guarantee for a known routed/dispatched target id. When a bundle id is supplied, the underlying trail read applies that bundle filter before the opened_at limit, so the result is a bounded bundle-local recent window rather than a global window narrowed afterward. Dispatch/inbox routing is closed_at-based, so absence from this opened_at listing is not proof that a known dispatched enactment or its steps do not exist; when a target id is known from dispatch, direct read_enactment_steps remains the grounding path. Do not require a routed target id to appear in list_recent_enactments before reading that target by direct id; if it is missing from the list but direct read_enactment_steps and read_bundle resolve, record the mismatch as a discoverability boundary. Increasing the limit may still omit a recently closed dispatched target whose opened_at falls outside the returned bundle-local window. When judging a dispatched target id, pair this with direct read_enactment_steps and preserve any list-versus-direct mismatch in observation_data as a discoverability boundary rather than treating listing absence as practitioner failure. If direct id reads and bundle resolution succeed, absence from this bounded recent list is a discoverability boundary, not evidence of practitioner misconduct. When judge_list_recent_enactments itself is code-owned and cannot persist a material-description amendment, this persisted affordance description is the durable closure surface for that list-versus-direct trail boundary.
