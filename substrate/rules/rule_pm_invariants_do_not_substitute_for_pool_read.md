id: rule_pm_invariants_do_not_substitute_for_pool_read
name: Invariants do not substitute for pool reads
---
When Practice Management is doing substrate stewardship, governed invariants that catch missing `pm_read_pool` after a write are guardrails, not permission to begin from reload, memory, documentation impact, or the write material itself. For affordance creation and bundle amendment in particular, even though `pm_create_affordance_requires_pool_read` and `pm_amend_bundle_requires_pool_read` will detect the determinable failure shape, the practitioner's work is still unfinished unless the current enactment records `pm_read_pool` for the relied-on pool before `pm_create_affordance`, `pm_amend_bundle`, or adjacent stewardship steps. If the pass has already reached a write-shaped material without that read, stop and backfill the relevant pool read or record the surface gap as a blocker before continuing.

Friction 645 confirms the quality evaluator is still finding the same authoring conduct after the deterministic invariants were added: the grounded failure is not every reload-only or documentation-only miss, but the concrete sequence `pm_reload_seed_substrate` followed by `pm_create_affordance` and `pm_amend_bundle` with no earlier `pm_read_pool`. Treat that sequence as a hard practice-quality stop. A Practice Management practitioner who sees the intended work will create an affordance, amend a bundle, or otherwise wire substrate must read the relied-on pool before reload or the first write; if reload has already happened without that read, the only valid next move before any write is the relevant `pm_read_pool`, and if a write already happened, the enactment must record the missing-pool-read blocker instead of using persistence, reload, documentation impact, or invariant coverage as completion.

Friction 965 confirms the same target sequence remains a live quality failure in another evaluated window despite active exact-material invariants and repeated bundle/rule prose: target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612` still shows `pm_reload_seed_substrate`, `pm_create_affordance`, and `pm_amend_bundle` with no `pm_read_pool`, while comparison enactments show the read path is available. For future Practice Management passes, do not answer this failure by adding another prose-only restatement after an ungrounded write. The first visible stewardship row must be the relevant `pm_read_pool`; once a create, amend, evaluation/invariant write, or bundle-wiring row has happened without it, the pass must stop with a concrete missing-pool-read blocker and no further substrate action, verification, documentation check, reload, closure, or rationale from the ungrounded change.
