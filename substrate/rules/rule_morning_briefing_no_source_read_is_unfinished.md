id: rule_morning_briefing_no_source_read_is_unfinished
name: No source read means the briefing has not started
---
Friction 706 confirms the same `reads_morning_sources_before_assembling` quality concern persists after prior source-gate wording: in the latest evaluated three-enactment window, unread Gmail was not read in any run, and the configured morning site list was skipped in two of three runs, with no concrete source blockers replacing those reads. Treat this as a first-work-product requirement rather than a reminder. A `morning_briefing` pass earns no briefing progress from a configured-site-list-only read, a direct Guardian/browser site check, an invalid URL site-check gap, live snapshot, supplied context, or final prose while either recurring source read is absent. The first visible briefing work must establish unread Gmail through `read_user_email` / `gmail_user_search_threads` or a concrete Gmail access/auth/data/material blocker; the second must establish the configured site list through `read_morning_site_list` / `read_morning_briefing_sites` or a concrete configuration/access/data/material blocker. If any other source, site-check, snapshot, synthesis, handoff, assembly, or final-answer step appears before both source facts or blockers are visible, stop that line immediately and backfill Gmail first, then the configured site list. If either source cannot be backfilled, close only by explicitly naming the blocked source surface and stating that the briefing did not reach its full grounding threshold; do not present partial source work as a completed morning orientation.

Friction 721 confirms the miss is still live in the next evaluated window: unread mail was absent in all three evaluated `morning_briefing` enactments, and two of those also lacked the configured usual-site-list read before other site-level work or briefing progress. Therefore the next `morning_briefing` pass must make the two-source ledger the first visible work product before any site check, live snapshot, source interpretation, assembly, handoff, or final answer: (1) `read_user_email` / `gmail_user_search_threads` for unread mail, or a concrete Gmail access/auth/data/material blocker; (2) `read_morning_site_list` / `read_morning_briefing_sites` for configured usual sites, or a concrete site-list configuration/access/data/material blocker. If the trail shows site-list-only progress, browser-site progress, invalid URL gaps, supplied context, or assembly while either ledger row is absent and unblocked, the pass is unfinished; the immediate next move is to backfill Gmail first and then the configured site list, or explicitly close as not fully grounded because the named source surface is blocked.

Friction 724 confirms this is still a genuine practice-quality stall across the next evaluated window: the target pass read only the configured site list and no unread email, while the two neighboring passes used browser or invalid-URL site-check paths without the unread-email read and without the configured usual-site-list read. Treat the two-source ledger as the entry product that must be visible before any source-specific work can count as morning-briefing progress. If the first visible move is a site-list read, the next move must be `read_user_email` / `gmail_user_search_threads` or a concrete Gmail access/auth/data/material blocker before any site interpretation, handoff, synthesis, or closure. If the first visible move is a browser site check, invalid URL gap, live snapshot, supplied source, or assembly attempt, stop immediately and backfill both ledger rows, Gmail first and configured site list second, unless concrete blockers for those exact source surfaces are recorded. Do not let site-list-only progress, one-off browser checks, invalid URL access gaps, live snapshots, or final prose satisfy `reads_morning_sources_before_assembling`; only the two recurring source reads or their explicit blockers make the pass ready to continue.

Friction 735 confirms the same practice-quality stall remained visible in the next evaluated window: the latest pass reached the configured site-list read without unread Gmail or a Gmail blocker, and the two prior evaluated passes recorded site-check activity without either recurring source read. Treat this as an interruption rule, not only an opening preference. The first morning-briefing source fact must be unread Gmail via `read_user_email` / `gmail_user_search_threads` or a concrete Gmail access/auth/data/material blocker; the second source fact must be the configured usual-site list via `read_morning_site_list` / `read_morning_briefing_sites` or a concrete site-list configuration/access/data/material blocker. If a pass has already read the site list first, the immediate next move is the Gmail unread read or blocker before any site interpretation, browser check, live snapshot, synthesis, handoff, final answer, or closure. If a pass has already entered browser/site-check work before either recurring source read, stop that site-check line and backfill both source rows, Gmail first and site list second, or close only by naming the exact blocked source surface and saying the morning briefing did not reach its source-grounding threshold.

Friction 742 confirms the recurring-source miss persisted after the prior interruption wording: across the evaluated three-enactment window, unread email was absent from all three passes and the configured usual-site list was absent from two. Treat this as source-ledger mode until the ledger is complete, not as a briefing pass with optional missing context. At the start of every `morning_briefing` enactment, and again after any accidental site-list, browser-check, live snapshot, supplied-source, synthesis, handoff, assembly, or final-answer move, inspect the two required ledger rows: unread Gmail via `read_user_email` / `gmail_user_search_threads`, then configured usual sites via `read_morning_site_list` / `read_morning_briefing_sites`. If either row is absent and unblocked, the next visible action must be the missing read, Gmail first, or a concrete blocker for that exact source surface; no other source work, interpretation, or closure may count as progress. If both rows cannot be made visible, the pass must close only as source-incomplete, naming the missing row(s) and the blocker, rather than producing a completed morning orientation from partial recurring-source evidence.

Friction 750 confirms this source-ledger requirement is still failing in the same two shapes: the latest evaluated pass read `read_morning_briefing_sites` without `gmail_user_search_threads`, and the two prior evaluated passes reached browser site-check work without either recurring source read. Treat a missing unread-mail row as the controlling unfinished state. If the current trail has a configured-site-list read but no unread-mail read and no concrete Gmail blocker, the next visible move must be `read_user_email` / `gmail_user_search_threads` or that blocker before any site interpretation, browser check, live snapshot, synthesis, handoff, final answer, or closure. If browser site-check work appears before both recurring rows, stop site-check progression and backfill Gmail first, then the configured site list, or close only as source-incomplete with the exact blocked source surface named. Do not count site-list-only progress or browser-check-first progress as delivery of the morning-briefing objective while either recurring source row is absent and unblocked.

Friction 772 confirms the same source-coverage gap persists after the latest evaluated three-enactment window: the target pass read `read_morning_briefing_sites` but omitted unread Gmail, and the two prior passes omitted both recurring source rows before downstream briefing work. Treat this as a source-ledger interruption at the moment any non-Gmail briefing move appears. If a `morning_briefing` enactment reaches the configured site-list read, browser/direct site checking, live snapshot, supplied-source interpretation, assembly, handoff, synthesis, or final answer before `gmail_user_search_threads` for unread mail is visible, the immediate next visible move must be `read_user_email` reaching `gmail_user_search_threads` or a concrete Gmail auth/access/data/material blocker. Only after that Gmail row is present or blocked may the configured site-list row be read or backfilled; only after both recurring rows are present or explicitly blocked may the pass continue into site interpretation, assembly, or closure. A site-list-only pass, browser-check-first pass, or partial-source pass is unfinished and must not be presented as a completed morning briefing.
