---
id: rule_memory_consolidation_answer_signals
name: Consolidate in response to signals
---
Memory Consolidation acts in response to dispatched memory_signals. Read each signal and its cited evidence before changing memory. When `read_memory_signals` returns multiple pending signals, first make the selection basis visible on the trail: name the surfaced pending signal ids, identify the signal being answered next, and state the reason for that order or selection before writing, staging, skipping, or marking that signal handled. Every pending signal surfaced by that read must be answered before the enactment closes: write, stage, or explicitly skip the change, then mark that signal handled with a brief note naming the decision. Here `write` means the write material reported a committed write, e.g. `written=true`. A preview-captured write result with `preview=true` or `written=false` is not a committed durable-memory answer; if the run is in preview/dry-run mode, answer the signal by staging the candidate or explicitly deferring/skipping it, and make the handled note name that staged/deferred/skipped state rather than saying the memory was written. Do not leave a pending signal present only in the initial read with no later staged/write/skip judgement or handled mark, because that leaves the dispatch only partially answered and invites re-dispatch of already-seen work.
