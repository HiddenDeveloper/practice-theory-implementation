Friction 674 confirms the Friction 670 burn-down pair still persisted across the next evaluated window: full mandate-inception/SPY benchmark total-return measurement and older/off-surface order reconciliation remained evidence-blocking while other rows advanced. The next stock-investor scheduled review is therefore a dedicated closure pass for those two rows, not an ordinary allocation review with burn-down attached. It must begin by reading fund state and the current follow-up register, then create a two-row closure ledger for benchmark total return and older/off-surface order reconciliation. For each row, execute the carried next action with the available stock-investor material surface or a cited current source; if execution is impossible, record the exact unavailable source, data, material surface, account/broker evidence, or time constraint and the next viable action. Do not open new allocation, sector/watchlist, macro, BRK-B/MSFT/ETF, or ordinary thesis narrative until both rows have one of these states: resolved with cited evidence, retired/deferred because it no longer gates current stewardship, or evidence-blocked after a concrete attempted or unavailable surface. If either row remains unchanged or merely re-narrowed, the decision summary must say the review remains evidence-blocked on benchmark-quality judgement or order/ledger confidence, and the follow-up register must schedule that unchanged row as the first action of the following review rather than presenting disclosed gaps as resolving.

Friction 678 confirms that the same benchmark total-return and older/off-surface order-reconciliation rows still recurred after the dedicated burn-down wording, so future stock-investor reviews must treat them as hard stewardship blockers until their state changes. At the start of the next scheduled review, before any allocation, thesis, or watchlist work, read fund state and follow-ups, then attempt those two rows directly. A row's state changes only if the review records one of: resolved with cited benchmark/order evidence, retired/deferred with a reason it no longer gates current fund stewardship, or blocked with the exact missing artifact/source/material/account evidence and the concrete next retrieval path. Merely carrying the row forward, narrowing the wording, or noting that other rows advanced is not resolution. If either row is still blocked at report time, the report and follow-up register must name `disclosed_gaps_are_resolving` as failing for this pass and keep the unresolved row as the first action of the following review; do not describe the gap set as resolving until both named rows have changed state.

Friction 682 confirms the same two rows kept recurring across eight evaluated passes, including after adjacent due items advanced, so the next stock-investor review must treat this as a stall-recovery pass rather than another periodic review. After reading fund state and follow-ups, the practitioner must make the benchmark total-return row and the older/off-surface order-reconciliation row the first substantive work items and must record, for each, a before/after state: prior blocker text, attempted source or material, returned evidence or exact failure, and resulting state. The resulting state may be only one of resolved, retired/deferred with a stewardship reason, or still blocked with a materially new retrieval path. If either row remains still blocked without a materially new retrieval path, the pass must stop ordinary allocation/watchlist/thesis expansion, record that `disclosed_gaps_are_resolving` failed again, and carry that row forward as the first follow-up; do not let progress on other rows, buys/sells, or report prose present the disclosed gap set as resolving.

Friction 687 confirms the stall continued even after attempted benchmark total-return and older-order reconciliation work: the same two rows remained evidence-blocking across the evaluated window. Therefore the next stock-investor review must not repeat the same unavailable-source attempt and carry the row forward unchanged. For each recurring row, compare the attempted source/material/account path against the prior blocker text. If the current attempt fails for the same reason as the prior pass, immediately pivot to a different acceptable closure path before any ordinary allocation work: use a documented proxy or alternate cited source, request or identify the exact external artifact needed, or retire/defer the row with a stewardship reason that explains why it no longer gates current fund decisions. A row may remain blocked only if the follow-up register records a materially new retrieval path with owner/source and next review trigger; otherwise the review must treat the pass as a failed stall-recovery, name `disclosed_gaps_are_resolving` as failed, and stop rather than presenting repeated disclosure as progress.

Friction 691 confirms that disclosure and attempted work still left the benchmark total-return measurement, older/off-surface order reconciliation, follow-up-register mismatch, and underconstruction blockers open across eight consecutive evaluated stock-investor enactments. The next stock-investor review is therefore a closure-forcing escalation, not another attempt-and-carry pass. After reading fund state and follow-ups, the first substantive section of the review must produce a blocker closure table for those four named rows. For each row, record the prior blocker, the attempted source/material/account path, whether that path is the same as a prior failed path, the fallback closure path chosen now, and the resulting state. The fallback closure path must be one of: resolved from cited evidence; resolved from a documented proxy with its limitation named; retired/deferred with a stewardship reason explaining why it no longer gates current fund decisions; or escalated to an exact external artifact/account action with owner and date because no projected material can close it. A row may not be carried forward as merely `underconstruction`, `older/off-surface`, `benchmark measurement gap`, or `follow-up-register mismatch` without that fallback closure path. If any row remains open after this table, the decision report and follow-up register must say `disclosed_gaps_are_resolving` failed again and make the single oldest still-open row the first and only stewardship blocker for the following review before new allocation or watchlist expansion.

Friction 695 confirms that the quality concern remained unresolved across the next evaluated eight-enactment window: benchmark total-return measurement, older/off-surface order reconciliation, and follow-up/register measurement gaps continued to be disclosed and carried forward even when adjacent rows advanced. Therefore the next stock-investor review must treat the closure table as the pass objective, not a prelude. After reading fund state and follow-ups, select the oldest still-open row from the recurring blocker set and drive it to one auditable terminal state before any new allocation, watchlist, thesis expansion, or ordinary reporting: resolved with cited evidence; resolved by a documented proxy whose limitation is named; retired/deferred with a stewardship reason; or escalated to a named external artifact/account action with owner and date. If no row reaches one of those states, the pass must stop, record `disclosed_gaps_are_resolving` as failed, and carry exactly that oldest row forward as the first and only stewardship blocker for the following review. Progress on adjacent rows, buys/sells, narrowed wording, or repeated disclosure must not be described as gap resolution while the same oldest blocker remains open.

Friction 699 confirms that the older/off-surface order-reconciliation gap has now carried from the oldest inspected pass into the latest inspected pass and remains decision-constraining even when some due items change state. Therefore the next stock-investor review must treat that specific older/off-surface order-reconciliation row as the first and controlling blocker unless it has already reached a terminal state in the current follow-up register. Before benchmark, allocation, watchlist, thesis, or other follow-up work, read fund state and follow-ups, then produce an order-reconciliation closure record with: the exact legacy/off-surface order or ledger uncertainty being reconciled; the account, broker, ledger, or prior-order artifact needed; the attempted projected material or cited external source; the returned evidence or exact unavailable-artifact result; and one terminal state. The terminal state must be one of: reconciled into the fund ledger with cited order evidence; retired/deferred with a stewardship reason explaining why the off-surface order no longer affects current holdings, cash, risk, or benchmark judgement; or escalated to a named external artifact/account action with owner and date. Do not carry the row forward as another generic older/off-surface disclosure, and do not describe `disclosed_gaps_are_resolving` as improving, until this order-reconciliation row has one of those terminal states.
