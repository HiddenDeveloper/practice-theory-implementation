---
id: rule_pm_pool_read_first_or_stop
name: Read the pool first or stop
---
For Friction 650's confirmed `uses_substrate_authoring_surface` quality concern, Practice Management substrate-stewardship work must treat a missing current-enactment `pm_read_pool` as a stop condition, not as a defect that a persisted write, reload, documentation-impact check, or deterministic invariant can repair afterward. Before any `pm_reload_seed_substrate`, `pm_check_documentation_impact`, `pm_create_*`, `pm_amend_*`, `pm_create_evaluation`, `pm_amend_evaluation`, `pm_create_invariant`, `pm_amend_invariant`, `pm_tombstone_invariant`, or `pm_amend_bundle`, first invoke `pm_read_pool` for the pool whose entries, ids, or material surface the pass will rely on. If the pass has already reached reload, documentation impact, authoring, amendment, invariant, evaluation, or bundle wiring without that pool read, the next move is the relevant `pm_read_pool` if no write has happened yet; if a write has already happened, stop further substrate action and record the missing-pool-read blocker instead of treating persistence or invariant routing as closure. This rule is additive to `rule_pm_read_pool_before_authoring` and `rule_pm_invariants_do_not_substitute_for_pool_read`: the older rules state the gate, while this one makes the repeated five-of-eight coverage failure an immediate conduct stop for future Practice Management enactments.

Friction 1037 confirms the same Practice Management quality failure remains in the evaluated eight-enactment window, including target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612`, which moved from `pm_reload_seed_substrate` into `pm_create_affordance` and `pm_amend_bundle` without `pm_read_pool`, while nearby passing examples used `pm_read_pool` before comparable writes. For future Practice Management passes, treat the first substrate-stewardship material itself as the interruption point: if `pm_reload_seed_substrate`, `pm_check_documentation_impact`, `pm_create_*`, `pm_amend_*`, evaluation or invariant work, or `pm_amend_bundle` would be the first stewardship row, the pass must instead produce the exact `pm_read_pool` for the relied-on pool or record a concrete pool-read blocker. If a write or bundle-wiring row has already happened without that read, do not continue to another write, reload, documentation check, verification, closure, or rationale from the ungrounded work; stop with the missing-pool-read blocker.

Friction 1041 confirms the same `uses_substrate_authoring_surface` quality concern remains active after the rule already named the entry gate: five of eight evaluated Practice Management enactments still reached reload, documentation-impact, authoring, amendment, or bundle-wiring surfaces without `pm_read_pool`, and target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612` again shows `pm_reload_seed_substrate` followed by `pm_create_affordance` and `pm_amend_bundle` with no pool row. For future Practice Management passes, the first substrate-stewardship material is the conduct boundary: before reload, documentation-impact checking, any `pm_create_*`, any `pm_amend_*`, evaluation or invariant work, or `pm_amend_bundle`, produce `pm_read_pool` for the exact relied-on pool. If reload or documentation-impact appears first, the only continuation is that exact pool read or a concrete pool-read blocker; if any write, evaluation/invariant write, or bundle wiring has already happened without it, stop the pass with the missing-pool-read blocker and do not proceed to further substrate action, verification, reload, documentation checks, bundle wiring, closure, or rationale from the ungrounded change.
