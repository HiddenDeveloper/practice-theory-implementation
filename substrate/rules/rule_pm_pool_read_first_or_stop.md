---
id: rule_pm_pool_read_first_or_stop
name: Read the pool first or stop
---
Friction 1179 confirms the same Practice Management `uses_substrate_authoring_surface` failure remains live after the bundle and selected rules already name `pm_read_pool` as the entry gate: five of eight evaluated enactments omitted `pm_read_pool`, including target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612`, which reached `pm_reload_seed_substrate`, `pm_create_affordance`, and `pm_amend_bundle` without the pool row. For future Practice Management passes, treat any intended substrate-stewardship surface as blocked until the exact relied-on pool is visible. Before `pm_reload_seed_substrate`, `pm_check_documentation_impact`, any `pm_create_*`, any `pm_amend_*`, evaluation or invariant work, or `pm_amend_bundle`, the first visible work product must be `pm_read_pool` for the pool supplying the ids or current content. If reload or documentation-impact checking has already appeared first, the immediate next move must be that missing pool read before any write. If an authoring, amendment, invariant/evaluation, or bundle-wiring write has already occurred without it, stop with a concrete missing-pool-read blocker; do not continue into further writes, bundle wiring, verification, reload, documentation checks, closure, or rationale from reload context, remembered ids, prior Smoother wording, or bundle prose.

Friction 1192 confirms the same Practice Management quality concern remains live despite the bundle description and selected rules already making `pm_read_pool` the entry gate: five of eight evaluated enactments again reached reload, documentation-impact checking, or substrate authoring/amending without the pool row, including target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612` moving through `pm_reload_seed_substrate`, `pm_create_affordance`, and `pm_amend_bundle`. For future Practice Management passes, treat absence of the pool row as the state of the work, not as context to explain after another stewardship action. If the next intended move is reload, documentation-impact checking, any `pm_create_*`, any `pm_amend_*`, evaluation/invariant work, or `pm_amend_bundle`, the immediate visible move must be `pm_read_pool` for the exact pool supplying ids, entries, or current content, or a concrete blocker naming why that pool cannot be read. If a create, amend, evaluation/invariant write, or bundle-wiring row has already occurred without that pool read, stop at a concrete missing-pool-read blocker naming the absent pool and ungrounded material; do not continue into verification, documentation checks, reload, closure, rationale, or any further substrate write from the ungrounded changed state.
