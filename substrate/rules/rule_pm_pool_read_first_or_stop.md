id: rule_pm_pool_read_first_or_stop
name: Read the pool first or stop
---
Friction 1149 confirms the `uses_substrate_authoring_surface` quality concern remains live even after the bundle description and related rules already name `pm_read_pool` as the entry gate: in an evaluated eight-enactment Practice Management window, five passes reached reload, documentation-impact, authoring, amendment, or bundle-wiring surfaces without the required pool row, including target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612` moving from `pm_reload_seed_substrate` to `pm_create_affordance` and `pm_amend_bundle`. For future Practice Management work, treat the first selected stewardship material as the gate, not the first successful write. Before `pm_reload_seed_substrate`, `pm_check_documentation_impact`, any `pm_create_*`, any `pm_amend_*`, evaluation or invariant work, or `pm_amend_bundle`, the immediate prior substrate-stewardship work product must be `pm_read_pool` for every ordinary pool whose ids or current content the move relies on. If a reload or documentation-impact row has already appeared first, the only valid continuation is the exact missing pool read or a concrete pool-read blocker. If a create, amend, evaluation/invariant write, or bundle-wiring row has already appeared without that pool read, stop the stewardship path with a missing-pool-read blocker; do not continue to further substrate action, verification, reload, documentation checks, bundle wiring, addressed closure, or rationale from the ungrounded write result.
