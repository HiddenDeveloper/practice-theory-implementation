---
id: rule_pm_pool_read_first_or_stop
name: Read the pool first or stop
---
For Friction 650's confirmed `uses_substrate_authoring_surface` quality concern, Practice Management substrate-stewardship work must treat a missing current-enactment `pm_read_pool` as a stop condition, not as a defect that a persisted write, reload, documentation-impact check, or deterministic invariant can repair afterward. Before any `pm_reload_seed_substrate`, `pm_check_documentation_impact`, `pm_create_*`, `pm_amend_*`, `pm_create_evaluation`, `pm_amend_evaluation`, `pm_create_invariant`, `pm_amend_invariant`, `pm_tombstone_invariant`, or `pm_amend_bundle`, first invoke `pm_read_pool` for the pool whose entries, ids, or material surface the pass will rely on. If the pass has already reached reload, documentation impact, authoring, amendment, invariant, evaluation, or bundle wiring without that pool read, the next move is the relevant `pm_read_pool` if no write has happened yet; if a write has already happened, stop further substrate action and record the missing-pool-read blocker instead of treating persistence or invariant routing as closure. This rule is additive to `rule_pm_read_pool_before_authoring` and `rule_pm_invariants_do_not_substitute_for_pool_read`: the older rules state the gate, while this one makes the repeated five-of-eight coverage failure an immediate conduct stop for future Practice Management enactments.

Friction 659 confirms the same quality signal remains live in the evaluated Practice Management window: five of eight enactments still lacked `pm_read_pool`, and the latest named target again shows `pm_reload_seed_substrate` followed by `pm_create_affordance` and `pm_amend_bundle` with no pool read. Treat that sequence as a pre-write branch, not as a recoverable afterthought. If a Practice Management pass intends to create or amend an affordance, material, rule, understanding, teleo-affective element, evaluation, invariant, or bundle wiring, the first stewardship step must be `pm_read_pool` for the relied-on pool before reload or any write. If reload has already happened without the read, the only valid next stewardship move before a write is that relevant `pm_read_pool`; if a write has already happened without it, stop further substrate action and record the missing-pool-read blocker instead of continuing from the persisted write, reload, documentation impact, or invariant coverage.
