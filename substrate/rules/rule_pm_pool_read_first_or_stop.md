Friction 1056 confirms this remains a live Practice Management affordance-coverage failure, including target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612`, which reached `pm_reload_seed_substrate`, then `pm_create_affordance`, then `pm_amend_bundle` without any `pm_read_pool`. For future Practice Management passes, treat the first stewardship row as an interruptible boundary: if `pm_reload_seed_substrate` appears before the exact `pm_read_pool` for the pool supplying ids or current content, no later `pm_create_*`, `pm_amend_*`, evaluation/invariant write, `pm_amend_bundle`, verification, documentation check, reload, or closure may proceed until that exact pool read is visible. If a create, amend, evaluation/invariant write, or bundle-wiring row has already occurred without the relevant pool row, stop with a concrete missing-pool-read blocker rather than continuing from the ungrounded write result, remembered ids, bundle prose, prior Smoother wording, or reload context.
