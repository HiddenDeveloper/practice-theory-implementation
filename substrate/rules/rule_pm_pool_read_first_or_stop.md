id: rule_pm_pool_read_first_or_stop
name: Read the pool first or stop
---
Friction 1080 confirms the remaining Practice Management failure is not limited to explicit writes: reload-only and documentation-impact-only paths are also substrate stewardship once they rely on pool-backed ids or current content. For future Practice Management passes, if `pm_reload_seed_substrate` or `pm_check_documentation_impact` would be the first stewardship row, the first visible work product must instead be `pm_read_pool` for the exact pool being relied on, or a concrete pool-read blocker. If a pass has already moved from reload or documentation context into `pm_create_*`, `pm_amend_*`, evaluation or invariant work, or `pm_amend_bundle` without that pool row, treat the work as ungrounded and stop further substrate action rather than continuing from reload context, documentation context, bundle prose, remembered ids, or prior Smoother wording.
