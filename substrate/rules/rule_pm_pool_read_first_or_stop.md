name: Read the pool first or stop
---
Friction 1142 confirms the Practice Management pool-read gate remains a live practice-quality failure after the bundle description and selected rules already name `pm_read_pool` as the entry condition: five of eight evaluated Practice Management enactments lacked any `pm_read_pool`, and target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612` moved from `pm_reload_seed_substrate` into `pm_create_affordance` and `pm_amend_bundle` without a pool read. For future Practice Management passes, treat the first stewardship surface reached without its relied-on pool row as an immediate stop, not as something later prose can excuse. If `pm_reload_seed_substrate`, `pm_check_documentation_impact`, any `pm_create_*`, any `pm_amend_*`, evaluation or invariant work, or `pm_amend_bundle` appears before the exact `pm_read_pool` for the pool supplying the ids or current content, no further stewardship action is permitted: the only valid next move is that exact `pm_read_pool` when no write has yet occurred, or a concrete missing-pool-read blocker when an ungrounded write or bundle wiring has already occurred. Do not continue into authoring, amendment, bundle wiring, verification, reload, documentation checks, closure, or rationale from reload context, remembered ids, bundle prose, prior Smoother wording, or ungrounded write results while the relied-on pool remains unread and unblocked.
