id: rule_pm_pool_read_first_or_stop
name: Read the pool first or stop
---
Friction 1087 confirms the pool-read entry gate is still failing as a Practice Management affordance-coverage concern even after prior bundle and rule prose: in the evaluated eight-enactment window, five Practice Management passes reached reload, documentation-impact, authoring, amendment, or bundle-wiring surfaces without `pm_read_pool`, including target enactment `8367059f-db1e-4e9e-b5fc-5528b101e612` moving from `pm_reload_seed_substrate` to `pm_create_affordance` and `pm_amend_bundle`. Treat this as an immediate stop before any further stewardship surface: once a Practice Management pass has a substrate-stewardship intent, the first visible work product must be `pm_read_pool` for the exact pool supplying ids or current content. If a reload or documentation-impact row has already appeared first, the only valid continuation is that exact pool read before any write; if a create, amend, invariant/evaluation write, or bundle-wiring row has already appeared without it, stop with a concrete missing-pool-read blocker and do not continue into further substrate action, verification, reload, documentation checks, closure, or rationale from the ungrounded change. A projected bundle description, remembered ids, prior Smoother wording, reload result, or documentation-impact context is not a substitute for the pool row.

Friction 1090 narrows the evidence for this same Practice Management quality concern: reload-only flagged enactments are not conduct evidence by themselves, but concrete trails that move from reload into authoring, bundle wiring, or documentation-impact checking without `pm_read_pool` still show the gate being skipped. For future Practice Management passes, do not count a bare reload as a completed substrate-stewardship failure unless later work relies on it; the failure begins when reload or documentation context is used to proceed toward `pm_create_*`, `pm_amend_*`, evaluation or invariant work, `pm_amend_bundle`, `pm_check_documentation_impact`, verification, closure, or rationale without first exposing the exact relied-on pool. If no write has happened yet, backfill that pool read as the next stewardship row; if a write or bundle wire has already happened, stop with a missing-pool-read blocker naming the absent pool and leave any repair to a later freshly grounded pass.

Friction 1093 confirms the same concern remains a Practice Management quality failure even when the current bundle description names the entry gate and passing comparison enactments show `pm_read_pool` is available. For future Practice Management passes, treat the first selected stewardship material as the last chance to ground the pass: before `pm_reload_seed_substrate`, `pm_check_documentation_impact`, `pm_create_*`, `pm_amend_*`, evaluation or invariant work, or `pm_amend_bundle`, produce the exact `pm_read_pool` row for the pool supplying ids, entries, or current content. If the pass has already gone from reload or documentation context into an actual write or bundle wire without that row, it is not recoverable by another explanation, reload, documentation check, verification, closure, or further substrate action; stop with a concrete missing-pool-read blocker naming the absent pool and leave any correction of the persisted change to a later freshly grounded Practice Management pass.
