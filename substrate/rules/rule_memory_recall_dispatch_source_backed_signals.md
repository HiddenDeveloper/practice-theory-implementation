---
id: rule_memory_recall_dispatch_source_backed_signals
name: Dispatch only source-backed memory signals
---
Dispatch a memory_signal only when it cites enough episode ids, graph node ids, checkpoint ranges, or canonical context to let Memory Consolidation inspect the claim. Source-backed means the cited basis is visible in this Recall enactment's own prior reads: every cited episode id, graph node id, checkpoint range, or canonical context should have been returned by a recall/read step in this pass before dispatch. When a signal compares against CanonicalContext, CanonicalProfile, CanonicalGuidance, or another durable canonical-memory node, first read that node through read_non_episodic_memory in the same pass so the comparison basis is visible on the trail; if the direct canonical read cannot be made, dispatch a bounded source-basis gap/no-op signal rather than presenting the comparison as grounded. This also applies to no-op or canonical-state claims that the canonical spine, satellites, or durable context are current, unchanged, corroborated, or pre-watermark: unless a same-pass read_non_episodic_memory grounds that canonical state, name the claim as an unverified canonical-basis gap rather than asserting it as known. about_the_user can ground the three engagement landing-node fields it returns, but it does not by itself ground satellite review, pre-watermark satellite coverage, or the currentness of the broader non-episodic memory layer; claims about those require read_non_episodic_memory in the same Recall pass or must be named as a canonical-basis gap. When citing episodic turns that are not visible in the recall_unreviewed_episodes result, first use recall_recent_engagement or recall_contextual_episodes so those turns appear on the trail; otherwise dispatch a bounded no-op or source-basis gap signal rather than attaching unseen source_ids. When a no-op or source-basis-gap signal reports a reviewed window or recommends advancing a reviewed range, its coverage claim must match the trail-grounded coverage returned by the reads in this pass: if recall_unreviewed_episodes returns a caveat, or if the earliest returned turn is later than the checkpoint/date floor, name the verified returned subrange and the caveated/unread interval separately; do not say the whole checkpoint-to-now window was read, and do not recommend advancing past a caveated gap unless a later read in the same enactment grounds that gap. If nothing relevant changed, dispatch a bounded no-op signal rather than inventing a memory candidate.
