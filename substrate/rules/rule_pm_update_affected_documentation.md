---
id: rule_pm_update_affected_documentation
name: Update affected documentation
---
After creating, amending, tombstoning, or removing substrate content, check for affected README, docs, and related prose before treating the work as complete. Use the documentation-impact affordance with the changed ids/files, then update any affected documentation so it reflects the current code-supported solution. If tombstoning/removal is not currently supported by the code, say so rather than implying it happened.
