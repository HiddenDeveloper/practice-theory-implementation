---
id: rule_adapt_after_failed_invocation
name: Reckon with failed invocations before closure or substrate action
---
A failed invocation is not discharged by later success: before any subsequent substrate amendment, reload_seed_substrate, or addressed mark, explicitly record whether the failed call changed the chosen amendment, was irrelevant to it, or remains a blocker. For closure specifically, that explanation must appear as its own pre-action reckoning or in another recorded step before `mark_friction_addressed`; putting the first explanation inside the mark rationale is rule neglect, even when the rationale names the failure accurately. Before any substrate amendment after a failed invocation, the closure-bearing reckoning must already be visible in a prior recorded step; the first explanation inside the substrate amendment's own arguments or result is too late and does not satisfy this rule. If the enactment will continue from a failed invocation into a substrate amendment, the prior recorded step must make the failure's bearing on that amendment auditable from the trail: either the corrected/adapted invocation or an intervening discovery/read result must show that the failure was only a material-name or argument-shape recovery for the same work item, or the enactment must stop with an explicit blocker/no-mutation disposition instead of amending. A corrected call that merely succeeds on the immediate retry is not enough for amendment authority unless the trail also shows why the failed call did not change the chosen amendment and is not a blocker.

When an `author_invariant` attempt fails because the invariant id already exists, that failure is not itself authority to continue into `amend_invariant`. Before amending the existing invariant, record through a valid projected step that the failed create only established the target already exists and did not change the chosen amendment, or inspect the relevant invariant/pool/catalog surface that makes the alternate amend target and unchanged amendment basis visible. If no such pre-amendment reckoning or read surface is available, stop with an explicit blocker instead of amending and explaining the failure later in the addressed rationale.

For Smoother dispatch in particular, a failed `read_pending_friction` attempt followed by a successful targeted read establishes the exact-Friction basis, but it does not by itself explain the failed attempt's bearing on a later `amend_pool_element`, `amend_affordance`, `amend_material`, `amend_bundle`, `author_invariant`, `amend_invariant`, `tombstone_invariant`, `author_evaluation`, `amend_evaluation`, or `reload_seed_substrate` action. Before any such substrate action, a separate prior recorded step must expose that the failed read was only material-name or argument-shape recovery and did not change the chosen amendment, or else the enactment must stop with a blocker/no-mutation disposition. If no projected note-like or schema-valid surface can carry that reckoning before the amendment, do not amend in that enactment.

Before invoking an affordance, use the material name and argument shape the active projection exposes; do not infer a material name from the affordance id, display name, or description. A generic string field in an input schema is not permission to invent a practice-mode or lifecycle value: if the value is optional and the projected material description or prior error does not expose an allowed value, omit it; if an invariant authoring call supplies `mode`, use only the detector value the surface accepts (`detect`), never `somatic` or `autonomic`. When an affordance or material invocation fails, read the error before acting again. A failure that enumerates the valid affordances or names alternatives is feedback, not noise: redirect to a named alternative, or correct the call to match what the projection actually affords. Record recovery through a valid projected surface only: do not add explanatory fields such as `prior_failure_reckoning` to a corrected material unless that material's input schema exposes such a field. If no note-like or schema-valid argument exists for the retried material, make the recovery basis visible through a valid corrective step, discovery/read step, or explicit blocker/no-mutation disposition instead of forcing prose into an unsupported argument. Do not re-issue the identical call verbatim — repeating a known-failing invocation unchanged ignores the guidance the error already gave and adds nothing to the trail. After any failed invocation, the enactment must record a follow-on reckoning before it closes: either a corrected/adapted invocation, a read that inspects the failure basis, or an explicit blocker/stop note naming why no grounded next action is possible. A corrected/adapted invocation only reckons with the failed call for the immediate retry path; if the enactment later proceeds to a substrate amendment, reload_seed_substrate, or addressed mark, the trail must also contain a pre-action reckoning that explicitly names the failed call's bearing on that later action or closure. That closure-bearing reckoning may be an explicit note, a corrected/adapted invocation whose result establishes the failure as only an immediate-call correction, or an intervening read whose result makes the failure's bearing visible, but it must appear before the substrate action or addressed mark. The first appearance of that explanation inside a substrate amendment or `mark_friction_addressed` is too late. If the enactment continues to a substrate amendment, reload_seed_substrate, or addressed mark after a failed invocation, that reckoning must be recorded before the next substrate action or closure mark, and must explicitly name the failed call's bearing on that closure: whether the failure changed the chosen amendment, was irrelevant to it, or remains a blocker. A later successful amendment, reload, or addressed mark cannot retroactively supply the missing reckoning for an earlier failed call. For dispatched Smoother work, a failed targeted read_pending_friction call remains a blocker: reload_seed_substrate or another substrate action is not a grounding substitute unless a later successful targeted read of the same friction_id appears in this same enactment before any amendment, reload, substrate action, or addressed mark. A later successful amendment is not by itself that reckoning. When mark_friction_addressed fails because the Friction id is not found or is already addressed, do not treat another identical empty read_pending_friction call as recovery. Record the disposition explicitly: the addressed mark did not persist because the id is absent/no longer pending/already addressed, and stop unless a distinct grounded recovery action is available. When the failed invocation is a substrate amendment whose target id does not resolve, changing to a different target id is not self-evidencing: before applying the alternate target, record the basis for that resolution through a catalog, pool, or bundle read/comparison, or stop and name the unresolved target as the blocker. A second failure does not discharge the rule; it renews the need to inspect or name the blocker rather than closing on unexplained failure.

When the Friction being addressed names a required substrate amendment or other visible substrate change, a failed amendment attempt plus a `no substrate mutation applied` rationale is not an addressed state. If the attempted amendment fails as duplicate, unpersisted, unreadable, or otherwise not applied, the Smoother must either apply a successful substantive amendment through a grounded alternate path, or stop with an explicit blocker/no-mutation disposition without marking that Friction addressed. Do not use `mark_friction_addressed` to close a required-amendment Friction from the same trail whose only amendment result failed or reported no mutation.
