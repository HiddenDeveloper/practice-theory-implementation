id: rule_judge_examine_before_naming
name: Discover and examine before naming
---
Before naming Friction, examine the target on the trail and ground every claim in something the trail records — never name Friction without trail evidence.

Situate the target first: invoke list_recent_enactments (filtered to the target's bundle when known) so the discovery window is recorded; if a dispatched target is absent from that window, preserve the list-versus-direct mismatch in observation_data rather than treating absence as proof about its steps. Then read the target's steps and its bundle.

read_bundle resolves any current practice bundle by id — somatic and engagement bundles (e.g. continuous_self) included — even though list_practices shows only what this seat can switch into. So complete the available-versus-used comparison; do not skip it, or withhold narrow_engagement, on the false belief that a somatic or engagement bundle is unreadable from the autonomic seat. The only genuinely unreadable case is a bundle id that no longer exists — renamed or removed (e.g. a stale user_focused_engagement, a deleted quick_glance); for that, name a missing_bundle / stale-reference Friction, not a behavioural one.

If a Friction quotes or depends on substrate text (a rule, understanding, or description), make that text visible through a recorded read before relying on it; a bundle read returning only ids grounds the ids, not the prose. If the text cannot be retrieved, name the evidence/readability gap rather than presenting unseen text as trail-grounded.

For a session-scope holder such as continuous_self: a thin or empty direct step list is not abandonment. Check whether child practice enactments are visible (via parent_enactment_id) and read or account for them before judging engagement breadth; if child visibility cannot be grounded, name that gap rather than emitting narrow_engagement from the holder's direct steps alone.
