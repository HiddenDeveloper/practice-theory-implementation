name: Substrate stewardship starts with pool read
---
For Practice Management, the first visible move of any substrate-stewardship path is `pm_read_pool` for the exact pool whose ids or current content the pass will rely on. This gate applies before reload, documentation-impact checking, `pm_create_*`, `pm_amend_*`, evaluation or invariant work, and `pm_amend_bundle`. If the pass cannot name the relevant pool, stop with a concrete substrate-surface blocker. If reload or documentation checking already happened without the pool read, backfill the relevant `pm_read_pool` before any write. If any authoring, amendment, evaluation/invariant change, or bundle wiring already happened without the pool read, stop further substrate action and record the missing-pool-read blocker; do not continue from persistence, bundle prose, prior trail memory, documentation context, or invariant coverage. This compact rule responds to Friction 747's repeated `uses_substrate_authoring_surface` miss by making the entry gate visible in the Rules surface rather than only in accumulated understanding or long historical repair prose.

Friction 751 confirms the same Practice Management quality concern remains live on the concrete authoring sequence `pm_reload_seed_substrate` -> `pm_create_affordance` -> `pm_amend_bundle` with no earlier `pm_read_pool`, even though the bundle description and deterministic invariants already name the gate. Treat this sequence as a failed stewardship branch, not as work made acceptable by later persistence or invariant routing: once a write or bundle wiring step has occurred without the pool read, the only proper continuation is to record the missing-pool-read blocker and stop further substrate action. The next Practice Management pass must make the pool read the first visible substrate-authoring product before reload, authoring, or bundle wiring.

Friction 760 confirms the remaining quality miss is still the same concrete authoring branch in enactment `8367059f-db1e-4e9e-b5fc-5528b101e612`: `pm_reload_seed_substrate` followed by `pm_create_affordance` and `pm_amend_bundle` with no same-enactment `pm_read_pool`, while a nearby passing case showed repeated pool reads were reachable. For future Practice Management substrate stewardship, do not treat reload-only or documentation-only missing examples as the decisive case; the decisive stop is any create/amend/evaluation/invariant/bundle-wiring step reached without the relied-on pool read. Once that write or wiring step has happened ungrounded, record the missing-pool-read blocker and stop rather than continuing from persistence, bundle description, documentation context, or invariant coverage.
