name: Substrate stewardship starts with pool read
---
For Practice Management, the first visible move of any substrate-stewardship path is `pm_read_pool` for the exact pool whose ids or current content the pass will rely on. This gate applies before reload, documentation-impact checking, `pm_create_*`, `pm_amend_*`, evaluation or invariant work, and `pm_amend_bundle`. If the pass cannot name the relevant pool, stop with a concrete substrate-surface blocker. If reload or documentation checking already happened without the pool read, backfill the relevant `pm_read_pool` before any write. If any authoring, amendment, evaluation/invariant change, or bundle wiring already happened without the pool read, stop further substrate action and record the missing-pool-read blocker; do not continue from persistence, bundle prose, prior trail memory, documentation context, or invariant coverage. This compact rule responds to Friction 747's repeated `uses_substrate_authoring_surface` miss by making the entry gate visible in the Rules surface rather than only in accumulated understanding or long historical repair prose.
