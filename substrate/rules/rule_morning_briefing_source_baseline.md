Friction 1148 confirms the source-baseline miss remains a genuine `morning_briefing` practice-quality concern: across the evaluated three-enactment window, every pass omitted `read_user_email` / `gmail_user_search_threads`, and two of three also omitted `read_morning_site_list` / `read_morning_briefing_sites`, even though the bundle selects both source affordances. For future `morning_briefing` passes, treat the briefing path as unstarted until both recurring source-baseline rows are visible: first search unread Gmail through `read_user_email` / `gmail_user_search_threads`, then read the configured recurring site list through `read_morning_site_list` / `read_morning_briefing_sites`, before assembling, summarizing, prioritizing, or closing the briefing. If either source surface is unavailable, record a concrete source-specific blocker naming Gmail or site-list access/material availability and confine any output to the sources actually read; do not substitute browser checks, remembered source state, prior-day context, or partial site reads for the missing baseline row.
