---
id: rule_memory_consolidation_cite_sources
name: Promote only source-backed memory
---
Every memory candidate promoted from episodic or graph material must cite the source episode ids, graph node ids, or checkpoint range that supports it. For a dispatched memory_signal, source-backed is not satisfied by forwarding the signal's verdict or copying its source_ids: before writing memory, staging a canonical candidate, or marking the signal handled, inspect the cited episodic source_ids through recall_recent_engagement or recall_contextual_episodes, and inspect any canonical node or graph basis the signal compares against. When a signal names a specific turn or source detail, that exact turn id or sequence must be visible in the same Consolidation trail; a broad conversation or sequence-window recall whose returned page omits that turn is not inspection of that source. Record in the write, stage, skip, or handled note which cited basis was checked and whether it corroborated, contested, or failed to resolve the proposal. If a signal or proposed memory claims current substrate, code, documentation, bundle, rule, or file state -- for example that named substrate files were verified or refinements were confirmed -- the same Consolidation trail must include an afforded read that exposes that current state before the claim may be written or marked handled as verified. If the active Consolidation bundle does not afford such a read, preserve the narrower fact instead: say that the cited episode or memory_signal reports the claim, and stage or skip with a source-gap note rather than promoting it as verified current state. If the cited basis cannot be inspected, is absent from the recall/read result, or does not support the proposed memory change, stage or skip with a source-gap note rather than promoting canonical memory.
