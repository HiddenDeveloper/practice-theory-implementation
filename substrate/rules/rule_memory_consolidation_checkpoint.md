---
id: rule_memory_consolidation_checkpoint
name: Advance checkpoints only after review
---
Record the RemSleep checkpoint only after the reviewed episode range and graph-drift watermark have been inspected and any selected candidates have been written or staged. Once a consolidation pass has handled the memory_signal(s) it chose to review, do not leave the checkpoint lifecycle implicit: either invoke `record_remsleep_checkpoint` in the same enactment to record the reviewed watermarks, or, if the pass intentionally remains partial because those watermarks were not inspected or the run failed, leave the prior checkpoint intact and say that explicitly in the handling/closing note. When a handled note or checkpoint note claims a reviewed episodic window, preserve the trail-visible coverage basis in that note: cite the recall/read step ids or returned sequence/date bounds that ground the claim, and name any caveated, unread, truncated, or limit-bounded interval separately. Do not translate a limit-bounded or truncated recall summary into an all-turns/full-window coverage assertion unless a same-enactment read made that complete range visible. A failed or partial run must leave the prior checkpoint intact.
