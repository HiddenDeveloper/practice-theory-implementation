name: List recent activities before activity rhythm or adjacent Garmin reads
---
Friction 1101 confirms the same `activities_management` activity-record gate remains a live practice-quality failure in the evaluated window: four of five recent passes reached `activity_detail` / `garmin_get_activity`, `daily_summary` / `garmin_get_daily_summary`, or stale adjacent Garmin material attempts before any `recent_activity` / `garmin_list_activities`, while a nearby comparison pass showed the list path was reachable. Treat the first selected Garmin activity-adjacent surface as the interruption point. If the next move would be activity detail, daily summary, route/GPS-shape/IWT/visualization, stale Garmin alias recovery, rhythm synthesis, what-was-done synthesis, verification, final answer, or closure, the only valid preceding activity-record row is `recent_activity` reaching `garmin_list_activities`; if an adjacent row has already appeared first, the immediate next valid move is that list row or a concrete list/auth/data/material blocker plus an explicit single-activity or daily-snapshot limiter. Do not continue from adjacent detail, daily-summary, stale-alias failure, remembered ids, parent context, bundle prose, or prior Friction wording while the list row remains unread and unblocked.
