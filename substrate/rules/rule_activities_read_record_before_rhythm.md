name: List recent activities before activity rhythm or adjacent Garmin reads
---
Friction 1182 confirms the same activities_management coverage drift remains a practice-quality failure after the rule and bundle description already named the entry move: four of five evaluated recent enactments still reached activity detail, daily summary, or stale adjacent Garmin materials without `recent_activity` / `garmin_list_activities`, while the contrast enactment showed the list path was reachable. Treat the list row as the first work product for any activity-rhythm, what-was-done, completed-activity mix, gaps, streaks, cadence, route/GPS/IWT, visualization, daily-summary, or adjacent activity-detail pass, including exact-date, exact-activity, supplied-id, or seemingly narrow detail requests. A supplied activity id, date, or user wording does not itself ground the activity record. If a detail, daily-summary, route/GPS/IWT, visualization, or stale material row appears before the list, the path is interrupted: the immediate next visible move must be `recent_activity` / `garmin_list_activities`, or a concrete list/auth/data/material blocker that explicitly limits the answer to supplied text or the isolated visible row. Do not continue into adjacent Garmin reads, synthesis, rhythm/what-was-done conclusions, verification, or final guidance from the unlisted row alone.

Friction 1189 confirms the remaining miss is not a need for more description but a failure to recover to the projected list surface after adjacent or stale Garmin rows. A failed material such as an unavailable activity-detail or daily-summary call is not activity grounding, and a successful adjacent row such as `garmin_get_activity` or `garmin_get_daily_summary` is not a substitute for the activity-list entry row when the pass is describing rhythm, what was done, activity mix, gaps, streaks, cadence, or activity context. After any stale Garmin material error or adjacent detail/daily-summary row appears before `garmin_list_activities`, the next visible activities_management move must be `recent_activity` / `garmin_list_activities`, or a concrete blocker naming list/auth/data/material unavailability and limiting any response to supplied text or the isolated visible row. Do not synthesize activity rhythm, compare days, infer completion patterns, or close with activity-context guidance from the failed or adjacent row alone.
