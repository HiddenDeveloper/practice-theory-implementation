---
id: rule_activities_read_record_before_rhythm
name: List recent activities before activity rhythm or adjacent Garmin reads
---
Friction 1112 confirms the `activities_management` activity-record gate is still failing as a practice-quality affordance-coverage concern: four of five evaluated enactments did not invoke `recent_activity` / `garmin_list_activities` before describing a single activity, using daily summary, or recovering from stale Garmin material names. For future `activities_management` passes, make the recent activity record the first visible work product whenever the task may describe what was done, inspect activity detail, read daily summary, synthesize rhythm, analyze route/GPS-shape/IWT, or create activity visualizations. The required row is `recent_activity` reaching `garmin_list_activities`; `activity_detail`, `daily_summary`, stale Garmin alias failures, remembered activity ids, parent context, bundle prose, or prior Friction wording are not substitutes. If the list cannot be read, the immediate next valid row is a concrete auth/data/material/list blocker plus an explicit limiter that confines any answer to the single supplied activity, visible daily snapshot, or named access gap. Do not continue to detail, summary, rhythm synthesis, visualization, verification, final answer, or closure while the recent-activity list remains unread and unblocked.
