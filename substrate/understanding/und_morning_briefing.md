name: A morning briefing is a triage ritual
---
The daily morning routine is a triage ritual over recurring sources: unread email accounts, usual sites, and any configured live snapshots. Each source should be read as a source with provenance, time, and account/site context. The output is not a comprehensive digest of the internet; it is a short orientation that separates items needing action, items worth watching, routine/no-action updates, and gaps the practice could not inspect.

The substrate has concrete Gmail reading and market snapshot materials. Recurring site checks should use the Cognabot browser JIT proxy material when a URL is available: the material opens the page through Cognabot's on-demand headless browser service, captures the browser accessibility-tree snapshot, and returns headline candidates, source notes, snapshot text, or a structured access gap. If the JIT proxy is unavailable, Docker cannot start the browser, a page fails to load, or the site list is unknown, the practice must name that gap rather than substituting a generic web summary.

Before assembling a morning briefing, ground the pass in both recurring source sets in the current enactment: invoke `read_user_email` reaching `gmail_user_search_threads` for unread mail, and invoke `read_morning_site_list` reaching `read_morning_briefing_sites` before checking or summarizing sites. These are source-coverage gates, not optional context. If Gmail or the configured site list cannot be read, name the access, data, or configuration gap in the briefing instead of treating the source as empty or replacing it with an ad hoc site check. Site-check captures and live market snapshots can deepen the briefing after those gates are satisfied, but they do not substitute for unread-mail and configured-site-list grounding.

Friction 649 confirms the remaining morning-briefing quality gap is specifically source coverage before assembly: recent passes read a configured site or performed a browser/site check while omitting `read_user_email` / `gmail_user_search_threads`, or omitted both recurring source reads, without a concrete Gmail or site-list blocker. Treat this as unfinished grounding. If the morning pass has not yet read unread mail through `gmail_user_search_threads`, that Gmail unread read is the immediate next move before site interpretation, browser checks, live snapshots, or final assembly; if Gmail cannot be read, record the auth, access, data, or material blocker in the briefing. A browser site check, invalid URL gap, supplied context, or final report prose does not satisfy either recurring-source gate unless the configured Gmail and site-list read, or their explicit blockers, are visible in the same enactment.

Friction 676 confirms the coverage failure persists across the evaluated morning-briefing window: one pass read only the configured site list and two passes skipped both recurring source reads before moving into site checks or assembly. Treat the two recurring reads as the opening floor of the practice, not as advice for the final report only. At the start of every `morning_briefing` pass, first invoke `read_user_email` reaching `gmail_user_search_threads` for unread mail and `read_morning_site_list` reaching `read_morning_briefing_sites` for the configured sites, or record the concrete Gmail/site-list access, data, configuration, or material blocker. If the pass has already touched a single source, browser site check, live snapshot, supplied context, or report assembly without both gates visible, the immediate next move is to backfill the missing recurring read before any further interpretation, site checking, or final briefing. A site-list-only pass is still unfinished until unread mail is read or its blocker is named; a browser-check-only pass is unfinished until both recurring source reads or their blockers are visible.

Friction 693 confirms the same source-coverage gate is still being missed across three recent morning-briefing passes: unread mail was never read or named as blocked, and two passes also reached site-level work without the configured site-list read or a concrete blocker. Therefore the next `morning_briefing` pass must treat any site-level step, browser check, live snapshot, supplied-source interpretation, or assembly attempt as an interruption point if both recurring reads are not already visible. Before another site check, snapshot, synthesis, or final briefing, backfill `read_user_email` reaching `gmail_user_search_threads` and `read_morning_site_list` reaching `read_morning_briefing_sites`, or explicitly name the Gmail/site-list access, data, configuration, or material blocker and limit the briefing around that gap. A configured-site read without unread mail is still unfinished; a browser or invalid-URL site check without the configured site list is still unfinished; no site-level evidence substitutes for the missing recurring-source gate.

Friction 717 confirms the remaining quality concern is source coverage at the beginning of the morning ritual: in the evaluated window, no recent pass recorded the unread-email material, and two also skipped the configured usual-site-list material before site-level work or assembly. The next `morning_briefing` pass should make a source ledger visible before interpreting any source: unread email via `read_user_email` / `gmail_user_search_threads`, configured usual sites via `read_morning_site_list` / `read_morning_briefing_sites`, or a concrete blocker for each missing source. If a pass starts with a site check, live snapshot, supplied context, or assembly, pause immediately and backfill this ledger before proceeding. Do not treat a site-list-only pass, a browser-check pass, or an assembled report as adequately grounded while unread email is absent and unblocked; do not treat any site-level evidence as covering the configured site list unless `read_morning_briefing_sites` or its blocker is visible in the same enactment.

Friction 727 confirms the source ledger still is not reliably shaping the first moves: in the latest evaluated three-enactment window, one pass read only the configured site list and two moved directly into browser site checks, including an invalid URL check, with no unread-email read and no concrete blockers for the missing recurring sources. Therefore the next `morning_briefing` pass must make the two-row source ledger the first visible work product before any site check, live market snapshot, supplied-source interpretation, synthesis, or final assembly: row one is unread email via `read_user_email` / `gmail_user_search_threads` or a concrete Gmail auth/access/data/material blocker; row two is configured usual sites via `read_morning_site_list` / `read_morning_briefing_sites` or a concrete site-list configuration/access/data/material blocker. If either row is missing, the pass is still in source-gathering mode; do not continue to browser checks, single-site interpretation, invalid-URL recovery, market snapshots, or assembled briefing prose until the missing row is read or its blocker is named in the same enactment.
